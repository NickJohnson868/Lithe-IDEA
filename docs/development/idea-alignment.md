# Windows IDEA 对齐验收

本轮先完成 Windows。外观以用户当前 IDEA 2026.2.2（262.10315.125）和提供的截图为基准，公开实现参考 JetBrains/intellij-community；已有能力全部保留。社区源码需固定到具体提交，并逐文件检查许可证及保留来源，不能把发行包中的所有资源都当作开源资源。

## 分阶段交付

| 阶段 | 验收内容 | 状态 |
| --- | --- | --- |
| 1 | 参考配置、现有能力清单、Release 基线 | 已记录配置与搜索基线；原生截图和 UI 时序待测 |
| 2 | 目录加载、搜索、工作区生命周期 | 待实现与验证 |
| 3 | 公共视觉规范、编辑器和目录高亮、已有界面 | 待实现与截图验证 |
| 4 | 分支菜单、Commit、差异、历史和版本比较 | 待实现与验证 |
| 5 | 全部现有能力回归、性能报告与资源清理 | 待验证 |

每阶段单独提交。实现状态和运行验证状态分别记录；没有运行证据的项目不得标为已验收。

## 参考与状态清单

已读取配置：编辑器 Islands Dark、Ubuntu Mono 17、连字开启。UI 字体、窗口大小、DPI、面板比例需要在参考截图中固定，不能从编辑器字体推断 UI 字体。

每个现有能力以 `shared/platform-feature-matrix.json` 为清单入口，检查正常、悬停、选中、失焦、加载、错误六种适用状态。视觉检查覆盖编辑器、项目目录、标签、工具窗口、菜单、弹窗、设置、终端、运行、AI 和 GitHub 面板。IDEA 没有直接对应界面的能力沿用统一视觉规范。

Git 检查顺序：顶部分支菜单 → Commit 工具窗口 → 双栏差异 → 提交历史及版本比较。包含键盘导航、快捷键、当前分支、跟踪关系、领先落后、最近分支、局部提交、冲突、重命名、二进制和多仓库状态。

## 性能基线与目标

此前在同机实际 Java 项目上测得 Release 全文搜索：常见词首批 141 条约 152ms，稀有词 24 条约 4702ms，无结果约 4686ms；这些是单次基线，不能当作 P95。文件打开、目录、输入、Git 历史和差异仍需补充端到端测量。

验收使用 Release；固定项目、数据、排除规则和结果上限，冷／热缓存分别记录。每组至少 20 次，报告 P50、P95、最大值与样本数。记录从用户事件到可见内容的时延，并分解 React、IPC、读取和索引时间。

目标：已加载目录 P95 ≤50ms；普通未加载目录展示 P95 ≤200ms；基线项目的稀有词与无结果全文搜索 P95 ≤1 秒。搜索输入、目录收缩和工作区切换不得等待后台扫描完成。目标未达成时保留实际数值与瓶颈，不能仅凭代码变化宣布达标。

## 回归与报告

- 目录：快速展开／收缩、空目录、连续单子目录、预加载去重、读失败重试、删除、工作区切换及关闭。
- 搜索：连续查询、取消、大小写、Unicode、正则、整词、分页、稳定排序和文件变更。
- 生命周期：重复打开、关闭、Java 重试、watcher 和后台任务释放。
- Git：新增／修改／删除／重命名／二进制／冲突、部分暂存、既有 index 内容、失败恢复、多仓库、快速切换差异和历史分页。

逐测试耗时由 `.agents/skills/write-stable-tests` 的标准 harness 生成到 `.artifacts/test-stability/`；机器路径、截图和实际项目数据只放本地 artifact，不写进产品常量。最终报告需明确未执行的平台检查、未达性能目标和未完成的截图对照。
