# Agent 笔记：Windows 全局文本搜索弹窗

状态：已实现

## 先说结论

Windows 的项目文本查找采用宽弹窗，范围固定为 In Project。大小写、整词、
正则、多行、文件掩码、上下文筛选、历史、固定窗口以及独立结果标签页使用
同一搜索会话。文本搜索必须先返回有界结果，不能等待 Java 符号索引完成。

## 问题

旧搜索挤在侧边栏，代码和路径难读。首次文本查询还会触发整个项目的内容
倒排索引和 Java 符号提取，在 Windows 调试构建的大项目上超过 15 秒。
文件名命中及 IDE 元数据又会消耗文本结果预算。仅改变弹窗外观无法解决这些问题。

## 决策

- 顶栏、活动栏、菜单及 Ctrl+Shift+F 统一打开弹窗，重复调用聚焦并选中查询。
  可见的大小写、整词、正则、文件掩码和上下文条件保留；旧侧栏隐含路径条件清空。
- 普通文本搜索复用 Core 的可见性规则及精确匹配器，达到结果上限即停止读文件。
  Windows 默认按项目忽略规则排除文件，并保留“包含忽略文件”开关。共享请求
  `respectIgnoreFiles` 缺省为 false，保持旧客户端语义；仅 Windows 项目查找显式启用。
  忽略遍历复用成熟的 ignore crate，支持嵌套规则与否定规则，禁用项目外父级和全局
  Git 配置，保留可搜索的点文件。更改开关使当前查询重新执行并淘汰旧请求。
- 已存在的内容索引能证明普通字面查询不可能命中的文件时，仅在文件长度和修改
  时间仍一致的情况下跳过读取。索引采用非阻塞锁，冷索引不等待构建；没有可靠
  文件身份、内容读取失败、新增或变更文件都进行精确扫描。正则和多行不使用此
  排除捷径。最终结果仍由当前内容的精确匹配器产生，不新增平行文本缓存。
- 文本读取只打开一次文件，最多读取现有大小限制加一个哨兵字节；大小写查询
  共用预计算的查询串，普通查询先判断全文是否包含目标再提取逐行匹配。Java
  索引原有固定正则只编译一次，不修改 JDTLS 语义事实归属。
- 原生请求携带取消标识和 15 秒期限，界面另有 1 秒通信容错余量；更换查询或
  关闭弹窗取消旧请求，旧结果不能覆盖新会话。失败提供重试。
- 文件掩码支持包含和排除；多行查询统一 LF/CRLF。上下文筛选由现有语言
  tokenizer（语法分类器）识别注释和字符串，不能通过字符串前缀猜测注释。
- 列表用黄色底色及深色字标出匹配，源码用 Monaco 的只读、虚拟化模型显示
  全文，保留语法着色并以绿色突出命中。预览不注册语言服务文档，关闭后释放模型。
- 分隔条复用现有 resizable 组件，尺寸局部管理。上下键/Enter 定位，多行输入
  使用 Ctrl+Alt+上下键选择，Ctrl+Enter 打开查找窗口。
- 弹窗通过通用 DialogResizeHandles 提供四边、四角缩放及方向光标；固定对边，
  限制最小尺寸和窗口边界。拖动按动画帧合并后只更新弹窗 DOM，不重绘搜索和
  编辑器；取消、失焦和卸载均释放监听、遮罩与光标。预览分隔条显示上下缩放光标。
- 宽高、结果/预览比例及固定开关复用现有安全 JSON 存储持久化；只在用户拖动
  结束时写入，恢复尺寸按当前窗口夹取。默认固定，失焦不关闭；用户取消固定后
  才允许点击外部关闭。拖动遮罩属于弹窗，不能触发外部点击关闭。
- 标题栏支持移动窗口，复用边缘缩放的指针会话、帧合并和清理逻辑；移动只改变
  左上坐标。位置和宽高一并保存，恢复时兼容只有宽高的旧记录，并按当前视口
  夹取位置，避免标题栏移出可见区域。标题栏内的交互控件不触发移动。
- 查找标签页保存结果快照。选择新标签页时保留旧查询；复用标签页时更新其
  快照。后续查询不能改写已有快照，结果页仍能加载后续页。
- 导航使用已接受的匹配范围加源码缩进，不能重新寻找该行第一个同名文本，
  否则“仅字符串”会跳到前面的注释命中。

## 考虑过的备选方案

只加宽侧栏无法改善全局输入和预览。把搜索超时加长只会掩盖首查依赖完整
符号索引的问题。为 UI 引入第二套索引会增加一致性负担，因此复用现有 Core
遍历与匹配层，单独改变文本查找的执行入口。源码预览复用 Monaco，避免手工
渲染整个大文件或重写语言着色。

## 后果

首批文本结果不再依赖语言服务或符号索引。热索引允许安全排除不命中的未变文件，冷扫描无结果时仍需读取整个可见
项目；请求有期限，单次查询最多 10000 个结果。上下文筛选依赖已支持语言的
语法分类；没有分类信息的纯文本属于普通内容。替换和额外搜索范围不在本次范围。

## 验证

- 前端用例覆盖超时取消、迟到结果、历史、选项、上下文入口、固定、键盘导航、
  独立结果页入口、匹配数量与异步预览竞态。
- Core 用例同时覆盖默认兼容、忽略规则、否定规则、热索引之后新增和变更文件。
- Core 用例覆盖 CRLF 多行查询、文件掩码排除、分类预算及现有共享搜索语义。
- 使用 `./.agents/skills/write-stable-tests/scripts/test-stability-windows.ps1 -Scope Frontend`、
  `./scripts/build-windows.ps1 -Configuration Release` 和原生 Cargo 测试验证。
- Windows 真实项目对比同一 `spring` 查询的冷启动耗时，并验证组合条件、
  无结果、源码预览、结果跳转和重复查询。

## 适用范围

`windows/tauri/src/features/global-search/`、Windows 搜索入口、结果标签页、
文件搜索适配器，以及 `rust/lithe-core/src/project/` 的共享文本匹配入口。
没有修改 macOS UI。
